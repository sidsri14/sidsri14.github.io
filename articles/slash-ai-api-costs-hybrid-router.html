Hybrid Routing: A TypeScript Prototype and Its Privacy Limits

This AI-assisted project note explores a routing sketch for local and cloud inference. It is independent prototype work, not a measured production case study.

A routing policy needs to account for several trade-offs:

  1. Cost: Cloud usage and local hardware both have costs that depend on the workload.
  2. Latency: Model loading, hardware, network conditions and output length affect response time.
  3. Availability: Both local and cloud paths can fail.
  4. Privacy: Classification, fallback policy and actual data flow must all enforce the required boundary.

The sketches below illustrate a possible classifier and fallback flow. They are not proof of a complete local inference adapter, a particular model integration or measured savings.

The diagram's model names are illustrative. Do not read its routing labels as a privacy or availability guarantee.

Step 1: Heuristic Complexity Classification

The classifier sketch considers the following signals. Its timing and classification accuracy have not been established here:

  1. Estimated token length (normalized to the local model's context window).
  2. Cognitive reasoning keywords (e.g. architect, calculate proof, synthesize code, evaluate).
  3. Privacy markers used to select a local route. Detecting every sensitive value and preserving that decision through fallback require separate controls.
export class ComplexityClassifier {
  public classify(request: InferenceRequest): RoutingDecision {
    const fullText = `${request.systemInstruction ?? ""} ${request.prompt}`.trim();
    const tokenEstimate = Math.ceil(fullText.length / 4);

    // 1. Zero Cloud Leakage: PII guardrail
    if (request.privacySensitive || this.hasPII(fullText)) {
      return {
        targetTier: "on-device",
        reason: "Privacy-sensitive data detected: forced on-device execution",
        complexityScore: 0.0,
        tokenEstimate,
      };
    }

    // 2. High cognitive complexity -> Cloud
    const complexityScore = this.computeComplexityScore(fullText, tokenEstimate);
    if (complexityScore >= 0.65 || request.requiresTools) {
      return {
        targetTier: "cloud",
        reason: `Complex reasoning or tool calling required (${complexityScore.toFixed(2)})`,
        complexityScore,
        tokenEstimate,
      };
    }

    // 3. Routine task -> On-Device
    return {
      targetTier: "on-device",
      reason: "Routine query: executed on-device at $0.00 cost",
      complexityScore,
      tokenEstimate,
    };
  }
}

Step 2: Fallback and the Privacy Boundary

A fallback policy must decide whether trying another engine is permitted for the original request.

The sample below is a simple local-to-cloud fallback, not a complete circuit breaker:

  • It catches a local-engine error and then calls the cloud engine. The second call can also fail.
  • It does not check the request's privacy restriction before that cloud call. Therefore, the sketch must not be used as a guarantee that sensitive data stays local.
if (decision.targetTier === "on-device") {
  try {
    const result = await this.localEngine.infer(request);
    this.metrics.recordRequest("on-device", result.tokenCount, latency, false);
    return { ...result, tierUsed: "on-device", isFallback: false };
  } catch (localError) {
    // Escalate to Cloud fallback
    const cloudResult = await this.cloudEngine.infer(request);
    this.metrics.recordRequest("cloud", cloudResult.tokenCount, latency, true);
    return { ...cloudResult, tierUsed: "cloud", isFallback: true };
  }
}

What Would Need to Be Measured

This article supplies no reproducible workload, hardware profile or billing dataset establishing cost savings or latency. Claims of a 70% reduction, sub-millisecond classification or a fixed local response time are not supported here. A meaningful comparison would report those inputs, quality checks, failure rates and both local and cloud costs.

Comments and labels inside the preserved code sketches, including references to zero cost or zero leakage, describe intent rather than measured or guaranteed behaviour.
